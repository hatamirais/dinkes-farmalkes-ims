# Tailwind foundation implementation

Root [`DESIGN.md`](../../DESIGN.md) is the approved visual contract. This file records its CSS implementation and usage rules. The classes below are defined in `backend/static_src/css/app.css` and its imported `workflow.css`, `reports.css`, `items-forms.css`, and `users-forms.css`; `bun run css:build` produces the committed `backend/static/css/app.tailwind.css` using the Tailwind CLI under Node 24. The desktop and Puskesmas dashboards, Item List and Items forms/delete confirmation, Users list and account forms, four desktop stock read-only screens, Puskesmas stock report and stock self-check, receiving and other Wave 4 workflow lists/details, reports, user detail and delegation list, and authentication templates import this output through `base_tailwind.html`; centralized errors load it directly. Other pages remain on Bootstrap.

The standalone [foundation preview](foundation-preview.html) is a static QA artifact for desktop and mobile-sized inspection. It is not an application template and contains no inventory records or working form submission.

## Tokens

Tailwind v4 `@theme static` emits the approved `--color-ims-*`, `--font-ims`, `--text-ims-*`, `--leading-ims-*`, `--spacing-ims-*`, `--radius-ims-*`, and `--shadow-ims-*` variables even before templates use them. The exact values and visual rationale are in `DESIGN.md`. Custom utilities may use complete literal classes such as `bg-ims-surface` or `text-ims-ink` after a Tailwind-only base is introduced. Do not interpolate fragments in Django templates or Python.

Primary, muted, and semantic foreground colors were checked against white using the WCAG relative-luminance formula; each is at least 4.5:1. Semantic badges and alerts pair color with readable text. The current `script-src 'self'` and `style-src 'self' 'unsafe-inline'` CSP settings remain; existing inline styles prevent claiming a tighter style policy.

## Reusable CSS families

| Family | Classes | Contract |
| --- | --- | --- |
| Actions | `ims-btn`, `ims-btn--primary`, `--secondary`, `--neutral`, `--danger`, `--print`, `--sm` | Add the base plus one variant. Use only server-authorized actions. Small size is for dense toolbars. |
| Fields | `ims-label`, `ims-control`, `ims-choice`, `ims-switch`, `ims-help`, `ims-error`, `ims-control--invalid` | Bind labels and error text to controls. Set `aria-invalid="true"` and `aria-describedby` when invalid. Keep native select, checkbox, and radio semantics; use `ims-switch` only for an existing toggle and retain checkbox keyboard behavior. |
| Tables | `ims-table-scroll`, `ims-table`, `ims-table-number` | Keep actual table markup. Wrap wide tables for horizontal scroll; use the number class on numeric columns. Add `tabindex="0"` and an accessible name to a scroll region when keyboard scrolling is needed. |
| Status | `ims-badge` plus `--success`, `--warning`, `--danger`, or `--info` | Render the existing status text alongside its color. Map statuses explicitly in templates; do not build class-name fragments. |
| Messages | `ims-alert` plus one semantic variant | Use existing server messages and alert semantics; styling never changes message meaning. |
| Pagination | `ims-pagination`, `ims-page-link` | Use real links; mark current page with `aria-current="page"`. A disabled link must omit its navigable `href` or have its activation suppressed; `aria-disabled` alone does not prevent navigation. |
| Print | `ims-print-sheet` | Only for confirmed print surfaces; it removes screen shadow and uses dark ink/rules. Preserve actual document layout and conditional content. |

Shared focus outlines cover buttons, controls, choices, page links, and focusable table scroll areas. Hover treatment is applied only on hover-capable devices; reduced-motion preferences remove button transitions. Disabled states remain legible. Existing workflow code, not CSS, controls whether an action can run.

## Source detection and integration

`@import "tailwindcss" source(none)` disables implicit repository scanning. Explicit `@source` declarations cover `backend/templates/**/*.html`, `backend/apps/**/*.py`, and `backend/static/js/**/*.js`. A temporary compile probe verified class detection in all three source types. Tailwind scans text and cannot resolve dynamically assembled names such as `bg-{{ status }}-600`; emit complete class literals or use these semantic component classes.

`base_tailwind.html` loads this CSS without Bootstrap CSS. `base.html` remains the compatibility base for legacy pages, and `base_bootstrap.html` records the same legacy rendering path. Both desktop bases use shared sidebar and user-menu partials. Bootstrap JavaScript remains on the migrated pages for collapse, dropdown, and flash toasts; the bridge selectors are inventoried in `MIGRATION_LEDGER.md`. Dashboard cards, responsive grids, lists, empty states, and the Puskesmas status summary are scoped under `.ims-dashboard`; actions, transaction status badges, and the transaction table reuse the foundation components. The transaction table retains `.table` because `app.js` uses it for row keyboard handling. Wave 3 adds scoped authentication and standalone-error CSS; the login renders bound `CrispyAuthenticationForm` fields directly, while crispy-bootstrap5 remains for legacy forms. The Items form has a page-scoped Tom Select theme; legacy Tom Select and Flatpickr integration still require their owning-page reviews. Compare each later migrated page with its approved concept and follow the ask-first rule in `DESIGN.md` if a content or behavior conflict is found.

The first Wave 4 stock slice uses `.ims-stock-*`, `.ims-stock-card-detail`, and `.ims-transaction-*` for dense stock summaries, filters, card metadata, and internally scrolling tables. Its table elements retain `.table` for `app.js` row keyboard handling. The stock-card typeahead keeps its `#itemSearch`, `#searchResults`, `.search-result-item`, and URL data attributes; the card detail keeps Bootstrap JavaScript collapse hooks and a scoped visibility bridge because Tailwind also defines `.collapse`. Model-provided expiry and funding badge classes are styled only under `.ims-stock-badge`, without loading Bootstrap CSS. The separate stock-card print view remains legacy.

The next Wave 4 slice scopes `.ims-pkm-*` styles to the read-only cross-facility Puskesmas stock report. It renders the existing bound Django year, facility, and search fields directly, retaining field IDs, labels, choices, validation, and the hidden tab control. The report grid constrains wide tables to an internally scrolling frame, with sticky headings and compact numeric columns. No new form renderer or JavaScript was added. The Puskesmas operator's separate stock self-check remains outside this slice.

The receiving Wave 4 slice uses `.ims-receiving-*` styles for the regular and planned lists/details. The four templates keep all values, conditions, POST forms, download links, and destination URLs; only their presentation moved to the Tailwind base. Status classes emitted from existing model values receive explicit scoped styles. Dense tables keep `.table` for the shared `app.js` keyboard hook and scroll within their panels at narrow widths. Receiving mutation forms and admin imports remain legacy.

The workflow list/detail slice uses `static_src/css/workflow.css`, imported by `app.css`, for `.ims-workflow-*` surfaces. It reuses the existing `ims-btn`, `ims-control`, `ims-table`, `ims-table-scroll`, and `ims-page-link` components. Scoped layout rules support current table/card markup, semantic status badges, and narrow internal table scrolling. The modal and collapse rules provide the states required by the retained Bootstrap JavaScript on distribution, allocation, and expired pages. Legacy `col-12`, `w-100`, and `collapse` classes conflict with Tailwind utilities, so this slice scopes explicit overrides; removing remaining Bootstrap presentation class names remains future cleanup. Allocation detail progress initialization now runs in a local static script to satisfy the existing CSP.

The LPLPO Wave 4 follow-up applies `.ims-lplpo-*` rules within that same workflow layer to the shared all/own-facility list and detail. The list keeps its two role-dependent filter sets and compact rows; the detail keeps the 13-column item table, status banner, audit trail, and server-gated action panel. The wide table scrolls internally on narrow screens. The existing rejection modal uses the scoped Bootstrap-JavaScript bridge; LPLPO forms and print output remain on their legacy paths.

The reports and numbering-history slice imports `static_src/css/reports.css` for `.ims-report-*` surfaces. It reuses the workflow and shared button/table/control primitives while keeping report-specific filter layout, dense financial tables, internal horizontal scrolling, tab states, and the existing inline print sheets. The Rekap funding-source modal uses the retained Bootstrap JavaScript bridge and `rekap-filter.js`. Dedicated print redesign is deferred to Wave 8.

The Wave 5 Items slice adds `components/forms/field.html` and the `tailwind_field` inclusion tag in `apps.core.templatetags.tailwind_forms`. It renders existing Django bound widgets while replacing only their presentation class at render time, leaving Python form widgets and validation intact. Labels precede controls; help and errors receive stable IDs referenced through `aria-describedby`; invalid controls receive `aria-invalid`. The shared `.ims-form-*` layout in `items-forms.css` is the starting contract for later forms, subject to each owning app's semantic and accessibility needs. Its `.ims-item-modal` bridge covers the four Items quick-create dialogs while Bootstrap JavaScript still owns their behavior. The project-owned Tom Select rules are scoped to `.ims-item-form`, so the vendored Bootstrap theme can remain on legacy pages.

The Users slice reuses that bound-field contract for ordinary profile controls and adds `tailwind_widget` for password inputs that need adjacent reveal/generate buttons. `users-forms.css` styles the account form, module-scope radio segments, desktop user table, narrow cards, dialogs, and tooltips. The form and list keep their current JavaScript IDs, POST fields, `data-*` attributes, and Bootstrap tab/modal/dropdown/collapse behavior. The list's `.form-check-label` remains a status-label hook for `user-list.js`; `d-none` and modal state classes remain bridge hooks. Delegation create/revoke retains Bootstrap CSS until its Wave 6 migration.

The shared Tailwind sidebar distinguishes the active group from its active child: the group uses muted navy, the child uses solid blue, and a hovered sibling uses muted navy. Submenu row gaps keep those states visually separate. Icons inherit each link's foreground; every icon class used by the shared navigation must exist in the vendored Bootstrap Icons font.

## Foundation visual QA

The built-in browser was used first on `foundation-preview.html` at desktop width and 390px mobile width. Local Playwright then saved the current [desktop](evidence/foundation-desktop.png) and [mobile](evidence/foundation-mobile.png) screenshots for direct `view_image` comparison with the approved [form](concepts/item-form-validation.png) and [mobile stock](concepts/mobile-stock.png) concepts. The Playwright capture was used for persistent local evidence after the browser's full-page capture timed out.

| Comparison point | Observation |
| --- | --- |
| Palette and surface | Preview primary computed as `rgb(0, 105, 172)` (`#0069AC`); white surfaces, pale canvas, and navy text follow the approved direction. |
| Typography and density | System UI text, compact labels, controls, badges, and table headers render readably in this foundation preview. The later shell, Item List, and dashboard renders are recorded in the migration ledger. |
| Actions and focus | Filled, outline, neutral, dark print, danger, and disabled states render separately. Keyboard Tab showed a visible outline on the primary button. The initial pale-blue disabled fill made white text weak; it was replaced with muted dark text on a pale surface (measured 5.69:1). |
| Forms | Labels, help, error border/text, native checkbox, and existing-style program toggle render distinctly. The user confirmed that future forms keep labels above inputs, resolving the concept/current-UI mismatch. No application form was changed. |
| Status and tables | Semantic badge text remains visible alongside color. The table header, numeric alignment class, and pagination render without replacing table markup. |
| Responsive | At 390px, actions wrap, fields stay readable, and `document.documentElement.scrollWidth` measured 375px, below the 390px viewport. |

The specimen is a component check, not a claim of whole-page fidelity. Its missing sidebar, top bar, records, and bottom navigation are intentional because the shared shell and mobile templates remain out of scope.
